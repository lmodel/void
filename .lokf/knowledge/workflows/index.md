# Workflows

* [Build and test (main.yaml)](main.md) - The Build and test workflow, `.github/workflows/main.yaml`: on every pull request and push to `main`, its test job runs `just test` on Python 3.10 to 3.14, and on 3.13 also `just lint` and `just lokf-adapt-check`, with `uv sync --locked`.
* [Lint & docs (lint-and-docs.yaml)](lint-and-docs.md) - The Lint & docs workflow, `.github/workflows/lint-and-docs.yaml`: on pull requests, pushes to `main`, Mondays and by hand, it runs ShellCheck, actionlint, the word budgets of CONTRIBUTING.md (1000) and SECURITY.md (900), markdownlint, lychee and codespell.
* [Upstream watch (upstream-watch.yaml)](upstream-watch.md) - The Upstream watch workflow, `.github/workflows/upstream-watch.yaml`: every Monday at 07:00 UTC and by hand, its void-sources job runs `scripts/check_upstream_release.py` against the VoID Note's page and the editors' repository, and on a finding opens or updates the issue titled Upstream watch: the VoID Note or vocabulary file has changed.
* [Semantic release (semantic-release.yml)](semantic-release.md) - The Semantic release workflow, `.github/workflows/semantic-release.yml`: on a pull request to `main` its plan job says what the merge would release; on a push to `main` its release job, in the `release` Environment, runs semantic-release from `.github/release/package-lock.json` and dispatches the knowledge release.
* [Knowledge Registrar (knowledge-registrar.yaml)](knowledge-registrar.md) - The Knowledge Registrar workflow, `.github/workflows/knowledge-registrar.yaml`, from the KTL sidecar: on a pull request that touches the bundle, on Mondays and by hand, it validates the bundle and runs the conventions script, and on a pull request it checks that each new human confirmation is backed by an approval or a signed commit.
* [Knowledge Librarian (knowledge-librarian.yaml)](knowledge-librarian.md) - The Knowledge Librarian workflow, `.github/workflows/knowledge-librarian.yaml`, from the KTL sidecar: every Monday at 05:00 UTC and by hand, once `KNOWLEDGE_LIBRARIAN_ENABLED` is `true`, it runs the ktl-librarian skill at the pinned KTL release in a read-only job and opens a review pull request from a job that runs no agent.
* [Knowledge Release (knowledge-release.yaml)](knowledge-release.md) - The Knowledge Release workflow, `.github/workflows/knowledge-release.yaml`, from the KTL sidecar: on a published release once `KNOWLEDGE_RELEASE_ENABLED` is `true`, or by hand, it validates and packs the bundle and attaches the bundle zip, the Copilot skill zip and the schema copy `schema-<tag>-void.yaml`, each with its `.sha256` and attestation.
* [Knowledge sync (knowledge-sync.yaml)](knowledge-sync.md) - The Knowledge sync workflow, `.github/workflows/knowledge-sync.yaml`, from the KTL sidecar: every Monday at 04:10 UTC and by hand, it compares the skills pin with KTL's newest release and opens or refreshes one pull request that moves the pin and the sidecar's copies, holding workflow changes for a reviewer.
* [Knowledge website (knowledge-website.yaml)](knowledge-website.md) - The Knowledge website workflow, `.github/workflows/knowledge-website.yaml`, from the KTL website templates: it builds the site on a pull request or push that touches its inputs, on Mondays and by hand, and deploys it to GitHub Pages from `main` once `KNOWLEDGE_WEBSITE_ENABLED` is `true`.
